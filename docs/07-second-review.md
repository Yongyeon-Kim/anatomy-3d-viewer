# 2차 기획 검증과 개선안

검토일: 2026-11-06. 대상: 기존 기획 문서 01~06. 사용자 확정 목표는 **웹 공개와 앱 스토어 등록을 완료한 탐색·학습·설명 서비스**다. 검토 결론은 문서와 공식 정책에 근거한 기획 판단이며, 사용자 실험·모델 품질·스토어 승인 검증을 완료했다는 뜻이 아니다.

## 종합 판단

후속 사용자 확인: 공부에 한정하지 않고 의사·일반인의 시각적 설명 자료로도 활용한다. 따라서 아래 검토 중 학습자만으로 대상을 좁히는 제안은 철회하고, 학습·설명을 각각 검증한다. [용도 확장 문서](09-exploration-and-presentation.md)가 이 부분의 최신 기준이다.

회전·분리·복원이라는 핵심 경험은 유지한다. 다만 현재 안은 탐색 체험 중심이므로, 반복 학습과 실제 출시를 위해 아래 다섯 가지를 보강한다.

1. 3D 관찰 뒤 오답 복습과 이어하기로 돌아오는 흐름.
2. 장기 분리, 근육 층별 보기, 내부 단면의 구분.
3. 내부 체험판과 정식 출시 콘텐츠의 별도 기준.
4. 웹·앱의 기록 저장, 모바일 성능, 다운로드 실패 상황.
5. 콘텐츠 검수·오류 수정과 스토어 제출 이후 운영.

기능을 더하는 것만으로 해결되지 않는다. **학습 대상·첫 과정 목록·모델 가용성**을 먼저 정해야 실제 제작 범위와 비용을 판단할 수 있다.

## 주요 발견과 수정 방향

P0는 개발 방식·콘텐츠 제작을 정하기 전에 해결할 항목, P1은 첫 정식 출시까지 필요한 항목, P2는 후속 확장이다.

| 우선순위 | 기존 안의 부족한 점 | 권장 변경 | 확인 방법 |
| --- | --- | --- | --- |
| P0 | 학습과 타인에게 설명하는 목적을 구분하지 않음 | 학습자·설명자·청자를 나누고 공통 3D 탐색과 목적별 화면 설계 | 학습 과제와 설명 과제를 별도 검증 |
| P0 | 20~30개 구조가 첫 출시 규모처럼 읽힘 | 내부 체험판 규모로 명시, 정식 공개는 과정의 완결성으로 판단 | 각 과정의 목표·구조·문제·검수 목록 대조 |
| P0 | 장기·근육에 같은 분리 방식을 적용할 여지 | 장기는 그룹 분리, 근육은 층별 노출을 기본으로 구분 | 두 종류의 장면을 각각 전문가 검토 |
| P0 | 자산 후보는 있지만 핵심 조작을 지원하는지 미확인 | 전신보다 첫 부위 샘플의 분할·좌표·용어·배포권부터 확인 | 자산 선정표 작성, 부적합 시 후보 변경 |
| P1 | 퀴즈 뒤 재방문 흐름이 없음 | 오답 모아보기, 학습 이어하기, 북마크 추가 | 종료 후 다시 열어 학습 위치와 오답 복원 |
| P1 | 전체 초기화에 의존 | 한 단계 되돌리기, 원위치 비교, 앞·뒤·옆 시점 버튼 | 숨긴 장기와 분리 상태를 잃지 않고 복귀 |
| P1 | 검색 결과와 현재 장면 연결이 불명확 | 동의어 검색, 숨김 해제, 해당 부위 이동, 장면 복귀 | 숨겨진 장기를 검색하는 과제 수행 |
| P1 | 원위치 관계 설명이 짧음 | 선택 장기의 주변 구조 함께 보기 | 분리 전후 위치 오해 확인 |
| P1 | 계정·저장 범위가 미정 | 손님 학습과 기기 내 저장을 기본으로 설계 | 가입 없이 첫 과정 완료, 기록 초기화 확인 |
| P1 | 모바일 실패 상황이 없음 | 로딩·재시도·낮은 품질·2D 설명 대체 경로 | 느린 통신·중단·메모리 부족 상황 점검 |
| P1 | 검수는 있으나 공개 후 정정 절차 없음 | 항목별 오류 신고, 검수 버전, 수정 이력 | 잘못된 문제 중지와 기존 오답 기록 처리 확인 |
| P2 | 개별 장기를 직접 당기면 조작 모드가 복잡해짐 | 묶음 분리 검증 후 제한 경로로 추가 | 회전과 장기 이동 혼동 여부 확인 |

사용자는 설명 용도를 명확히 포함했다. 설명하는 사람이 전문가여도 듣는 사람은 초보자일 수 있으므로 쉬운 용어와 상세 용어를 상황에 맞게 전환한다.

## 추가 기능의 우선순위

### 첫 정식 출시에 권장

| 기능 | 제공할 가치 | 범위 제한 |
| --- | --- | --- |
| 자유 탐색·학습·설명 | 목적에 맞는 조작과 콘텐츠 제공 | 첫 화면에서 세 진입점 제공 |
| 관계 보기 | 기관 이름과 주변 배치를 함께 이해 | 검수된 관계만 표시 |
| 오답 복습 | 틀린 구조를 다시 찾아보게 함 | 초기에는 간단한 복습 목록, 자동 알고리즘 제외 |
| 장면 북마크·이어하기 | 같은 장면과 학습 단계로 복귀 | 우선 현재 기기에 저장 |
| 단계별 설명 | 입문자에게 어려운 용어 부담 완화 | 쉬운 설명과 상세 설명 두 단계 |
| 오류 신고 | 잘못된 라벨·문제를 고칠 경로 | 구조 식별자·콘텐츠 버전 자동 첨부 계획 |
| 조작 도움과 대체 버튼 | 터치·마우스·키보드에서 조작 이해 | 처음 한 번 안내, 필요 시 다시 열기 |

학습 단계는 ‘아직 안 봄 → 관찰함 → 문제 풂 → 다시 복습할 항목’으로 구분한다. 한 번 정답을 맞혔다고 ‘완전히 습득’으로 표시하지 않는다.

### 권리와 수요 확인 후 추가

- 선택 계정과 기기 간 동기화: 웹에서 공부한 내용을 앱에서 이어 볼 필요가 확인되면 도입. 로그인 후 손님 기록 합치기와 중복 처리까지 함께 설계한다.
- 학습 묶음 다운로드: 오프라인 권리와 모델 용량 확인 후 도입. 진행률·취소·재시도·삭제·버전 갱신을 한 묶음으로 계획한다.
- 복습 알림: 사용자가 복습 시간을 선택하는 방식. 알림이 없어도 학습 기능은 사용할 수 있게 한다.
- 근육 작용과 경로 학습: 한 관절의 움직임이나 한 경로로 한정하여 검수한다. 장기 간격 조절과 별도 콘텐츠다.

AI 대화 교사, 커뮤니티, AR·VR, 환자 영상 업로드, 병변·수술 시뮬레이션은 초기 요구에 추가하지 않는다. 현재의 핵심 가설을 검증하는 데 필수적이지 않고 별도 콘텐츠·운영 범위를 만든다.

## 정식 출시 콘텐츠 기준 제안

내부 체험판의 3개 과정·15~20개 문항은 조작 검증용이다. 첫 정식 버전은 ‘전신 해부학 완성판’ 대신 **흉부·복부 입문 과정**처럼 실제 제공 범위를 명확히 소개한다.

출시 범위는 아래 조건으로 판단한다. 특정 문항 수가 스토어 승인을 보장하지는 않는다.

- 공개할 모든 과정에 학습 목표, 필요한 구조, 설명, 확인 문제, 오답 피드백이 있다.
- 부위·계통 경로에서 같은 항목을 찾아도 이름·설명이 일치한다.
- 주요 구조를 보기 위해 필요한 주변 뼈·근육·경계가 준비되어 있다.
- 각 목표를 이름 찾기와 위치 관계 등 서로 다른 방식으로 확인한다.
- 빈 카테고리나 아직 제작하지 않은 과정을 판매 범위처럼 노출하지 않는다.
- 설명·모델·정답을 검수하고, 공개 모델의 대표 범위와 생략 사항을 안내한다.

## 사용자 경험 검증 시나리오

아래는 후속 시안·실기기 검증에 사용할 과제다. 아직 수행하지 않았다.

| 과제 | 관찰할 실패 |
| --- | --- |
| 가입 없이 첫 과정 시작 | 계정 생성 요구 때문에 학습을 시작하지 못함 |
| 회전 후 특정 장기 찾기 | 인체의 좌우와 화면 좌우 혼동 |
| 확대 후 장기 간격 벌리기 | 두 동작을 같은 기능으로 이해 |
| 정상 배치와 분리 배치 비교 | 분리 상태를 실제 위치로 기억 |
| 가려진 구조 검색 후 원래 장면 복귀 | 검색할 때 학습 문맥이 사라짐 |
| 오답을 확인하고 다음 날 재방문 | 틀린 항목·진도가 없어 처음부터 다시 시작 |
| 앱을 닫고 같은 과정 이어하기 | 위치·선택 상태·학습 단계 소실 |
| 라벨 없는 퀴즈 풀기 | 검색·설명에서 정답이 노출됨 |
| 연결 중단 후 다시 열기 | 빈 화면, 무한 로딩, 오류 설명 없음 |
| 모델을 보지 못하는 환경에서 설명 읽기 | 3D 로딩 실패가 전체 학습 실패로 이어짐 |

초기 5~8명 중 80% 이상이 도움 없이 회전·분리·복원 과제를 수행하는 것을 사용성 목표로 제안한다. 분리 상태를 정상으로 오해한 사례는 비율과 관계없이 원인을 검토한다. 소규모 검증으로 교육 효과를 일반화하지 않는다.

실기기 성능의 초기 목표는 선정한 기준 기기에서 회전 중 30fps 수준, 첫 학습 화면 진입 5초 이내, 15분 연속 학습 중 중단 없음으로 제안한다. 기기·통신·모델 크기·캐시 조건을 함께 기록하고, 큰 자산의 최초 다운로드 시간은 별도로 측정한다. 이는 실측 결과나 확정 사양이 아니다.

## 개발 전에 닫아야 할 결정

1. 탐색·학습·설명 사용자와 공개할 과정·장면 목록.
2. 첫 부위를 지원하는 모델·용어·배포 조건.
3. 앱 대상 OS와 공개 순서, 예산 범위.
4. 손님 학습만으로 시작할지, 첫 출시부터 동기화할지.
5. 무료 범위와 유료화 여부, 콘텐츠 유지 비용.
6. 의학 검수 담당과 모델 수정 담당을 확보할 방법.

기획 수정은 진행할 수 있지만 모델 적합성·학습 효과·스토어 등록 가능성을 확정하려면 각 단계의 증거가 더 필요하다. 출시 준비는 [웹과 앱 출시 계획](08-release-plan.md)에 연결한다.
