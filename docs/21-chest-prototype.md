# 흉부 3D 조작 시제품과 검증 기록

작성일: 2026-11-06. 대상: #15–#19, 상위 #8.

## 현재 결과

흉부 58개 메시·6개 선택 묶음을 사용하는 **로컬 내부 조작 시제품**을 구현했다. 회전·확대·선택 중심 관찰, 숨기기·선택만 보기·전체 표시, 간격 조절·배치 복원을 제공한다. 실행 환경의 자동 브라우저 검증과 화면 검토까지 수행했다. 웹 공개, 실물 휴대폰 확인, 의학 전문가 검수와 사용자 실험은 완료하지 않았다.

## 실행

Node.js 22.12 이상 또는 Node.js 24와 npm이 필요하다. 이번 환경은 Node.js 22.23.2, npm 10.9.8이다. 저장소 루트에서 실행한다.

```sh
npm ci
npm run dev
```

터미널에 출력되는 `http://127.0.0.1:5173`을 브라우저에서 연다. 해당 포트를 이미 사용 중이면 Vite가 다른 포트를 출력한다. 개발 서버는 기본적으로 현재 컴퓨터에만 열린다. 모바일 에뮬레이션은 실제 휴대폰 접속·측정을 의미하지 않는다.

```sh
npm run build
npm run preview
```

빌드 결과는 `dist/`이며 미리보기의 기본 주소는 `http://127.0.0.1:4173`이다. 파일을 직접 더블클릭하는 방식은 지원하지 않는다. 개발·빌드는 자산 복사 전에 원본 SHA-256을 검사한다. 누락·불일치 시 빌드를 중단하며 임의의 외부 모델로 대체하지 않는다.

### 필요한 로컬 자산

다음 원본이 있어야 한다. 현재 작업 컴퓨터에는 모두 존재한다.

- `research/samples/chest-review/chest-smooth.glb`: 3,861,948 bytes, 58개 메시.
- `research/samples/chest-review/lungs-smooth.glb`: 203,056 bytes, 5개 메시.

`npm run assets`가 `public/models/`로 복사하며 `predev`·`prebuild`에서 자동 실행된다. 원본과 복사본·빌드 결과는 Git에 포함하지 않는다. **새 clone에는 모델이 없다.** 이 컴퓨터의 검증된 파일을 같은 경로로 옮기거나 [자료 재현 절차](../research/README.md)에 따라 원본을 확보하고 Blender의 `prepare_chest_review.py`, Python의 `summarize_chest_review.py`로 생성·검사해야 한다. 원본 버전·해시·내부 출처는 보존한다. 생성 시 렌더를 생략하려면 Blender 명령에 `-- --skip-renders`를 전달할 수 있다.

GLB와 매핑 명세는 [19 문서](19-chest-quality-and-prototype-readiness.md)를 기준으로 한다.

## 구현 구성과 임시 기술 선택

- Three.js `GLTFLoader`: 준비된 GLB를 그대로 읽으며 geometry를 재중심화하거나 모델 축을 추가 회전하지 않는다.
- `OrbitControls`: 마우스·터치의 회전·확대·화면 이동. 별도 프레임워크 없이 Vite로 로컬 실행·정적 빌드를 구성했다.
- `src/model.js`: 원본 이름·선택 묶음 검증, 원본 행렬 보관, 선택·표시·간격 상태 관리.
- `src/main.js`: 장면·카메라·입력·로딩 오류 처리와 UI 연결.
- `src/style.css`, `index.html`: 한국어 UI와 반응형 배치. 한글 글꼴은 Noto Sans KR Variable을 빌드에 포함하여 외부 글꼴 API를 호출하지 않는다. 글꼴 라이선스는 `public/licenses/`에 동봉한다.
- `tests/model.test.mjs`, `tests/browser/`: 실제 자산 수치 검사와 브라우저 통합 조작 검사.

첫 실험을 빠르게 반복하고 GLB·웹 입력을 직접 검증하기 위한 선택이다. 정식 웹·Android·iOS 렌더러·패키징 방식의 확정은 #11에 남긴다. 서버·로그인·장면 저장·공유·퀴즈·전신·절단·조직 변형은 이번 범위에 없다.

## 조작과 상태 규칙

| 동작 | 결과 |
| --- | --- |
| 모델 클릭·탭 / 목록 선택 | 6개 묶음 중 하나를 색과 경계 상자로 강조. 빈 곳 클릭·선택 해제·Escape로 해제 |
| 드래그 / 한 손가락 이동 | 현재 회전 중심을 기준으로 회전. 드래그 종료는 선택 탭으로 처리하지 않음 |
| 휠·확대 버튼 / 두 손가락 핀치 | 카메라 거리 변경. 모델 크기 기반 최소·최대 거리 제한 |
| 오른쪽 드래그 / 두 손가락 이동 | 관찰 중심을 화면 안에서 이동 |
| 선택 중심으로 보기 | 선택 구조 경계 중심을 회전 중심으로 설정하고 선택 영역에 맞춰 관찰 |
| 숨김·표시 | 묶음 전체 표시 변경. 선택한 묶음을 숨기면 선택 해제. 숨긴 구조는 표시 버튼으로 다시 열기 |
| 선택만 보기 | 선택 묶음만 표시. 간격·카메라·모델 위치는 변경하지 않음 |
| 전체 다시 표시 | 모든 사용 가능한 묶음 표시. 간격·시점·선택 유지 |
| 구조 사이 간격 | 확대와 별도 슬라이더. 원본 행렬 + 묶음별 월드 변위로 매번 계산 |
| 배치만 복원 | 원본 행렬로 복원. 선택·숨김·시점 유지 |
| 카메라 초기화 | 원본 흉부 전체를 보는 기본 시점. 배치·표시·선택 유지 |
| 화면 초기화 | 기본 카메라·전체 표시·원본 배치·선택 없음으로 복원 |

간격 0은 ‘원본 배치’, 1–100은 ‘설명용으로 벌린 배치’로 표시한다. 묶음별 고정 방향으로 원본 경계상자 대각선의 최대 약 29%만큼 이동한다. 좌우 폐는 좌우, 심장 묶음은 앞, 흉곽은 뒤, 횡격막은 아래, 기관은 위로 이동한다. 이는 비교용 배치이며 장기 연결·생리 운동·안전한 실제 이동 경로의 모델이 아니다. 원본 행렬에서 계산하므로 슬라이더 누적 이동을 하지 않는다.

glTF는 Y-up이다. 원본 Blender Z-up에서의 변환은 `(x, y, z) → (x, z, -y)`이며 GLB에 이미 반영되어 있다. 앞·뒤·옆 버튼은 각각 glTF +Z·−Z·+X 방향의 관찰 시점이다. 해부학적 방향·단위의 전문가 확인은 남아 있다. 객체 이름은 Three.js가 정제한 이름 대신 GLTFLoader의 노드 원본 이름과 매핑 명세를 대조한다.

초기 파일 로딩은 20초 후 중단 안내를 제공한다. HTTP 실패·잘못된 GLB·이름/수 불일치는 오류로 처리하고 재시도·폐 단독 대체 경로를 제공한다. 폐 대체 모델에서는 2개 묶음만 사용 가능하며 나머지는 비활성화한다. 페이지를 새로 열면 흉부 전체를 다시 시도한다. WebGL 2 사용 불가 시 원인을 안내한다. 그래픽 컨텍스트 손실 시 조작을 중지하고 복구 이벤트 후 모델을 다시 읽는다.

## 재현 가능한 검증

```sh
npm test
npx playwright install chromium
npm run test:browser
npm run build
```

Playwright는 `4173` 포트를 사용한다. 사용 중인 다른 서비스가 있다면 종료하거나 설정에서 포트를 함께 바꾼다. Linux에서는 Chromium 실행용 시스템 라이브러리가 필요하다. 이번 컴퓨터에는 libnspr4·libnss3가 없어 Ubuntu 패키지를 `/tmp/anatomy-browser-libs`에만 추출했다. 시스템 패키지와 전역 Node 패키지는 변경하지 않았다. 이 환경에서의 실행 명령은 다음과 같다.

```sh
LD_LIBRARY_PATH=/tmp/anatomy-browser-libs/usr/lib/x86_64-linux-gnu npm run test:browser
```

자동 검사 범위:

- 실제 흉부 GLB의 메시 58개, 삼각형 240,979개, 묶음별 수 `2/3/4/47/1/1`, 원본 이름과 GLB 노드 행렬 보존.
- 브라우저에 읽힌 메시의 표면 경계를 원본 Blender 좌표로 되돌려 이전 검사 기록과 1e-6 원본 단위 미만으로 일치하는지 확인. 원본 Blender 행렬은 내보내기 시 분해·형상 반영될 수 있어 행렬 자체의 단순 직접 비교로 동일성을 주장하지 않는다.
- 실제 자산으로 1,000회 간격 변경·복원 후 모든 로컬·월드 행렬의 원본 일치 및 최대 오차 **0** 확인.
- 데스크톱/휴대폰 크기의 Chromium에서 로딩→회전→선택·중심 관찰→숨김·단독 보기→간격→복원. 표시 반복, 복원 독립성, 캔버스 raycast, 키보드·휠·거리 제한, 가로 넘침 확인.
- 터치 에뮬레이션에서 한 손가락 회전·두 손가락 핀치·취소 후 다음 탭 확인.
- HTTP 404·잘못된 GLB·대체 모델 실패·20초 시간 초과·재시도·WebGL 불가·그래픽 컨텍스트 손실 및 복구.

원시 결과·스크린샷·첨부된 모델 상태는 `test-results/`에 로컬 보관한다. 요약은 [prototype-verification.json](../research/results/prototype-verification.json)에 기록한다. 데스크톱과 모바일 에뮬레이션의 원본/벌린 배치 스크린샷을 직접 열어 형상 표시·한글·선택 강조를 확인했다. 사람을 대상으로 한 사용성 시험은 아니다.

최종 결과는 수치 검사 **3개 통과**, 브라우저 **15개 통과·1개 의도적 생략**이다. 생략은 데스크톱 프로젝트에서 중복되는 터치 전용 검사이며 실물 휴대폰 검사 통과를 뜻하지 않는다. 실제 프로덕션 빌드도 별도 preview에서 58개 메시 표시·선택·간격·복원과 글꼴 라이선스 제공을 확인했다. 정상 통합 경로에서 페이지 오류가 없었고, WebGL 불가 주입 검사의 콘솔 오류는 예상 결과다.

빌드 후 별도 터미널에서 `npm run preview -- --port 4174 --strictPort`를 실행하고 `npm run test:production`으로 빌드 결과를 검사한다. 모든 검사가 끝난 뒤 `npm run verify:summary`로 요약을 갱신한다. 이 두 명령도 Linux 브라우저 라이브러리가 없으면 위 `LD_LIBRARY_PATH`가 필요하다. 요약에 기록된 로컬 파일 읽기·파싱·첫 렌더 시간은 해당 headless 실행 1회의 참고값이며 HTTP 전송·실물 기기 성능 목표의 달성 근거로 쓰지 않는다.
