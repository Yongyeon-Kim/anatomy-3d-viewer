# 웹 공개와 앱 스토어 등록 계획

작성일: 2026-11-06. 사용자 확정 목표는 **웹과 앱을 실제 이용 가능한 상태로 출시**하는 것이다. 현재는 기획 단계다. Android·iOS 모두 검토 대상으로 두고, 최종 지원 플랫폼과 출시 순서는 개발 범위를 확정할 때 결정한다.

## 전체 진행 단계

사용자 확인에 따라 출시 대상은 학습뿐 아니라 의사·일반인의 시각적 설명 도구다. [탐색과 설명 용도](09-exploration-and-presentation.md)를 반영하여 설명 화면과 자료 활용도 검증한다.

| 단계 | 결과물 | 완료를 판단할 증거 |
| --- | --- | --- |
| 1 기획 확정 | 대상, 학습 과정, 조작 흐름, 우선순위 | 핵심 결정과 제외 범위가 문서화됨 |
| 2 자료 검증 | 모델 샘플, 용어 연결, 권리 기록 | 회전·분리·정상 배치와 배포 조건 확인 |
| 3 시안 검증 | PC·모바일 화면과 학습 시나리오 | 조작 혼동을 관찰하고 수정함 |
| 4 구현 | 공통 학습 콘텐츠와 플랫폼별 제품 | 핵심 학습 과정을 처음부터 끝까지 수행 |
| 5 비공개 시험 | 웹 시험 환경, 앱 시험 배포 | 의학 검수, 실기기, 저장·복구 확인 |
| 6 공개 준비 | 도메인, 운영 페이지, 스토어 제출 자료 | 공개 범위·지원 기기·지원 창구 확정 |
| 7 공개와 심사 | 운영 웹, 앱 심사 제출·보완 | 웹 접속 가능, 대상 스토어 승인 |
| 8 출시 확인 | 공개 URL·스토어 링크·운영 기록 | 실제 설치 후 핵심 학습 가능 |

웹 베타를 먼저 열고 앱 시험 배포를 진행하는 순서를 권장한다. 단, 앱용 터치 조작·저장·성능·모델 이용 권리는 기획 초기부터 검토한다. 웹 완성 후 앱 요구를 처음 검토하는 일정은 피한다.

앱 등록은 제출 버튼을 누른 시점에 끝나지 않는다. 심사 보완과 승인 후 배포 확인을 포함한다. 심사 기간과 승인 여부는 사전에 보장할 수 없다.

## 웹 공개 준비

- 도메인과 운영 주체를 정하고 HTTPS로 접속할 수 있게 한다.
- 검색·과정·3D 학습 화면의 주소를 직접 열거나 새로고침해도 동작하게 한다.
- 지원 브라우저·기기에서 로딩, 터치, 작은 화면, 3D 실패 시 설명 보기를 확인한다.
- 소개, 학습 범위, 출처, 개인정보 안내, 이용 안내, 문의·오류 신고 페이지를 준비한다.
- 계정이 있다면 삭제·복구 정책을 적용하고, 결제가 있다면 구매·복원·환불 안내를 실제 동작과 맞춘다.
- 오류 감지, 백업, 잘못된 콘텐츠를 수정하거나 이전 버전으로 되돌리는 방법을 준비한다.

## 앱 등록 전에 기획할 사항

| 항목 | 기획 결정 | 준비물 |
| --- | --- | --- |
| 플랫폼 | Android·iOS 지원과 공개 순서 | 최소 OS·기준 기기 목록 |
| 배포 주체 | 개인·조직과 실제 제품 분류에 맞는 계정 | 개발자 계정, 본인·조직 정보, 필요한 등록 비용 |
| 제품 정체성 | 해부학 학습 범위와 앱 이름 | 아이콘, 설명, 실제 화면 이미지 |
| 콘텐츠 범위 | 장기·근육·해부 이미지 표현 | 연령·콘텐츠 등급 질문에 대한 정확한 응답 |
| 정보 처리 | 진도·오답·로그 등 실제 수집 범위 | 개인정보 문서와 스토어 데이터 공개 항목 |
| 심사 접근 | 손님 학습 또는 로그인 필요 여부 | 필요한 경우 심사용 계정과 이용 안내 |
| 수익화 | 무료·유료 콘텐츠와 제공 지역 | 해당 스토어의 결제 정책에 맞는 판매·복원 흐름 |
| 운영 | 공개 후 문의와 수정 담당 | 연락처, 지원 페이지, 배포·수정 절차 |

계정 등록, 비용 결제, 계약은 후속 실행 단계의 작업이다. 현재는 계정을 만들거나 앱을 제출하지 않았다.

## 확인한 공식 정책과 기획 영향

### Apple

Apple은 최소 기능 기준, 개인정보 공개, 계정 생성 시 앱 내 계정 삭제 등을 심사 기준으로 안내한다. 단순 웹 링크 모음 수준을 피하고 실제 학습 기능과 모바일 사용성을 제공한다. 특정 프레임워크를 사용한다는 이유로 승인 또는 거절을 단정하지 않는다. 디지털 콘텐츠 유료화는 판매 지역·방식에 맞는 결제 조건을 별도 검토한다. [App Review Guidelines 4.2, 5.1.1, 3.1](https://developer.apple.com/app-store/review/guidelines/)

### Google Play

2023-11-13 이후 생성된 개인 개발자 계정은 공개 배포 접근 신청 전에 최소 12명이 연속 14일 이상 참여하는 비공개 테스트 요건이 있다. 해당 계정 유형일 때 일정에 반영하며, 기간 충족이 자동 공개 승인을 의미하지 않는다. [공식 테스트 요건](https://support.google.com/googleplay/android-developer/answer/14151465?hl=en)

앱에서 계정을 만들 수 있게 한다면 앱 내부 삭제 경로와 외부 웹 삭제 요청 경로를 준비한다. [계정 삭제 요건](https://support.google.com/googleplay/android-developer/answer/13327111?hl=en)

건강 관련 기능·정보를 제공하는 앱에 대한 정책과 Health apps declaration을 확인한다. 우리 제품은 해부학 교육을 목적으로 기획하며, 실제 제공 기능에 맞춰 선언 항목·계정 요건을 검토한다. ‘교육’이라는 이름만으로 관련 정책이 적용되지 않는다고 판단하지 않는다. [Health Content and Services](https://support.google.com/googleplay/android-developer/answer/16679511?hl=en)

정책 확인일은 2026-11-06이다. 출시 시점에 대상 국가·계정 유형·기능에 맞춰 다시 확인한다. 개인정보·결제·계정 요건은 실제 제공 기능에 따라 달라지므로 지금 모든 기능을 추가하는 근거로 사용하지 않는다.

## 저장과 오프라인의 제품 결정

첫 출시의 기본 제안은 가입 없이 학습하고 현재 기기에 진도·오답·북마크를 저장하는 것이다. 기기 변경이나 앱 삭제로 기록을 잃을 수 있다는 점을 저장 화면에서 설명한다. 기기 간 이어하기가 첫 출시의 핵심 요구로 확정되면 선택 계정과 동기화를 출시 범위에 올린다.

오프라인 묶음은 원본 모델의 저장·재배포 권리와 용량을 확인한 후 결정한다. 미지원이라면 오프라인에서도 기록과 안내를 열 수 있게 하고, 3D 학습은 연결이 필요하다는 상태를 표시한다. 지원이라면 다운로드 완료된 묶음과 온라인 전용 항목을 구분한다.

## 공개 후 운영

| 상황 | 대응 계획 |
| --- | --- |
| 라벨·정답 오류 | 항목 식별자와 버전을 확인하고 수정, 필요 시 문제 일시 중지 |
| 모델 업데이트 | 저장 장면과 구조 식별자 호환 확인, 실패하면 안내 후 기본 장면 제공 |
| 충돌·학습 화면 중단 | 지원 기기·재현 조건 확인, 수정본 시험 후 배포 |
| 학습 기록 손실 | 저장 범위와 백업·동기화 상태를 확인하는 지원 경로 |
| 유료화 시 구매 문제 | 스토어 거래 상태·복원 동작과 제공 권한 확인 |

## 프로젝트 완료 기준

아래는 향후 실제 출시 완료를 판단할 기준이며 아직 달성한 항목은 없다.

- 공개 웹 주소에서 지원 브라우저로 핵심 과정을 완료할 수 있다.
- 확정한 대상 스토어에서 앱이 승인·공개되고 실제 기기에 설치된다.
- 웹과 앱에서 같은 구조·설명·문제가 일관되게 제공된다.
- 회전·선택·분리·복원·문제 풀이·기록 저장이 작동한다.
- 설명 모드에서 관심 부위를 찾아 강조하고, 저장한 설명 장면으로 돌아오는 흐름이 작동한다.
- 이미지 출력이나 장면 공유를 제공한다면 실제 배포 권리·출처 표시·수신자 열람을 확인한다.
- 공개 콘텐츠의 검수와 출처·사용권 기록이 정리되어 있다.
- 설명한 오프라인·동기화·결제 범위가 실제 동작과 일치한다.
- 문의·오류 수정·업데이트를 운영할 수 있다.
