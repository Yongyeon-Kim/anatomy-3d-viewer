# 개발 전 기획 진행 순서

지금은 대상 학습자와 핵심 경험을 좁히고, 그 경험을 지원할 자료가 있는지 확인하는 단계다. 기술 스택과 전체 개발 견적은 범위와 모델 후보를 정한 뒤 산정한다.

이 문서는 개발 전 단계의 계획이다. 사용자 확정 목표인 웹 공개·앱 등록까지의 전체 과정은 [출시 계획](08-release-plan.md)에서 이어진다. 2차 검토에서 추가된 복습·저장·출시 기준은 [기획 검증](07-second-review.md)을 따른다.

## 권장 진행 순서

| 순서 | 할 일 | 산출물 | 다음 단계로 넘어가는 기준 |
| --- | --- | --- | --- |
| 1 | 학습 대상과 공부 상황 확인 | 대표 사용자·학습 목표 1장 | 첫 대상 집단을 한 가지로 좁힘 |
| 2 | 흉부·복부 첫 학습 범위 선정 | 구조물 목록, 과정 3개, 문제 초안 | 각 항목이 학습 목표에 연결됨 |
| 3 | 모델 후보의 권리·범위 비교 | 자산 후보 비교표 | 선택·분리 가능성과 배포 조건 확인 |
| 4 | 화면과 조작 설계 | PC·모바일 와이어프레임, 조작 설명 | 확대와 분리가 별개로 이해됨 |
| 5 | 전문가 검토 | 용어·배치·설명·문제 검토표 | 핵심 오류와 누락이 정리됨 |
| 6 | 학습자에게 기획안 검증 | 관찰 기록과 수정 우선순위 | 조작 혼동과 분리 상태 오해를 줄임 |
| 7 | 초기 제품 범위 확정 | 요구사항, 제외 범위, 비용 항목 | 개발 착수 여부를 판단할 수 있음 |

비개발 기획 산출물은 약 2~3주 작업 묶음으로 계획할 수 있으나, 인력·모델 접근·검수자 일정에 따라 달라진다. 확정 일정이나 개발 기간의 추정은 아니다. 현재 수행한 일은 초기 자료 조사와 문서 초안 작성이다.

## 사용자 확인 방법 제안

입문 학습자 5~8명과 해부학 교육 경험자 1~2명을 초기 인터뷰 대상으로 가정한다. 표본 규모는 정성적 문제 발견용이며 교육 효과를 입증하기 위한 연구 설계가 아니다.

인터뷰에서는 아래를 확인한다.

- 지금 어떤 과목을 공부하고, 어느 부위에서 가장 자주 막히는가.
- 이름 암기와 위치 관계 이해 중 어느 문제가 더 큰가.
- 현재 쓰는 책·앱에서 어떤 장면을 이해하기 어려운가.
- 주로 사용하는 기기는 무엇이며, 한 번에 얼마나 공부하는가.
- 장기를 벌려 보는 화면이 어떤 점에서 도움되거나 혼란스러운가.

기획안에는 ‘선택 → 회전 → 간격 조절 → 복원 → 문제’의 화면 상태를 순서대로 보여 준다. 종이 또는 클릭형 시안으로 조작 의미는 검증할 수 있지만, 실제 3D의 공간 이해와 조작감까지 검증한 것으로 판단하지 않는다.

실제 학습 효과는 후속 단계에서 같은 난이도의 사전·사후 문제와 지연 복습 결과를 비교한다. 2D 자료 대비 효과를 주장하려면 비교 조건, 사전 지식, 충분한 참여자 등을 갖춘 별도 평가가 필요하다.

## 초기 성공 기준 초안

아래는 정성적 판단 기준이다. 후속 실기기 검증용 목표치는 2차 검증 문서에서 제안하며 아직 확인된 결과가 아니다.

| 기준 | 확인 방법 |
| --- | --- |
| 확대와 분리를 설명할 수 있음 | 두 조작을 보여 주고 차이를 자기 말로 설명하게 함 |
| 처음 보는 구조를 선택하고 복귀할 수 있음 | 진행자의 개입 횟수와 막힌 지점 기록 |
| 분리 상태를 실제 배치로 오해하지 않음 | 정상 배치를 고르는 질문과 이유 확인 |
| 학습 후 위치 관계를 설명할 수 있음 | 원위치 화면에서 위치 관계 문제 풀이 |
| 다시 공부할 이유가 있음 | 다음 복습 상황과 사용할 기기를 구체적으로 질문 |

작은 인터뷰에서 발생한 오류의 원인을 먼저 고친다. 체류시간이 길다는 이유만으로 학습 효과가 좋다고 결론 내리지 않는다.

## 준비할 역할과 비용

| 역할 | 책임 | 비용을 좌우하는 요소 |
| --- | --- | --- |
| 기획·학습 설계 | 대상, 과정, 화면 흐름 | 학습 과정과 문제 수 |
| 해부학 검수 | 용어, 모델, 위치 관계, 설명 | 구조물 수, 전문 깊이, 수정 횟수 |
| 3D 자산 담당 | 모델 분할·정리·표현 품질 검토 | 원본 상태, 내부 구조, 필요한 가공 |
| UX 담당 | PC·터치 조작, 설명과 학습 흐름 | 지원 기기, 사용자 검증 횟수 |
| 후속 개발 담당 | 확정 요구의 구현 가능성 검토 | 플랫폼, 오프라인, 저장·동기화 |

모델 이용료뿐 아니라 정리·검수·콘텐츠 집필 비용을 포함해야 한다. 기능과 자산 상태가 정해지지 않은 현재 단계에서 총액을 제시하면 오차가 크다.

## 아직 결정하지 않은 사항

| 항목 | 임시 제안 | 확정에 필요한 정보 |
| --- | --- | --- |
| 주요 사용자 | 한국어 입문자·보건계열 초급 | 사용자 인터뷰 |
| 첫 부위 | 흉부·복부 주요 장기 | 선호 과목과 모델 가용성 |
| 표현 방식 | 이해하기 쉬운 해부학 표현 | 실사감과 학습 난이도 선호 |
| 모델 출처 | BodyParts3D 우선, Z-Anatomy·상용 연동 비교 | 파일별 권리·구조·품질 |
| 앱 출시 순서 | 웹·앱 공통 경험을 먼저 설계 | 오프라인 필요, 예산, 주 기기 |
| 수익 모델 | 미정 | 개인·기관 수요와 콘텐츠 원가 |
| 한국어 표기 기준 | 쉬운 이름·영문·동의어 검색 | 용어집 판본과 전문가 검수 |

## 다음 기획 작업의 구체적인 결과물

이 초안을 바탕으로 **첫 학습 과정 3개의 상세 스토리보드와 구조물 목록**을 만든다. 이후 모델 후보를 확인하고 PC·모바일 화면을 그리면 개발자가 구현 범위와 필요한 자료를 판단할 수 있다.

전체 인체 확장은 초기 학습 경험을 검증한 다음 결정한다. 앱 배포, 상용 계약, 원본 모델 구매와 실제 구현은 현재 작업에 포함하지 않는다.
